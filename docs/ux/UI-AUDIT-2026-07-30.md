# UI Audit — 30 juli 2026

**Scope:** `/control`, `/operator`, `/operate`, `/editor`, `/layout`, `/project`, `/compose`  
**Methode:** multi-agent static audit (geen live UI-wijzigingen; poort 2014 onaangeroerd)  
**Agents:** control, operator/operate, editor/project/layout/compose  
**Doel:** kritische UX-review — niet meteen redesignen; eerst productkeuzes

## Verdict

De **desktop live-flow** (overlay-kaart → Go live) en de **operator touch-kern** (score/clock) zijn in de basis goed. Het product voelt echter als **meerdere half-gekoppelde apps**: control vs operate vs operator, editor vs layout vs project. Belangrijkste risico’s: **Main/Solo-outputmodel**, **tablet op /control**, **operate≠operator parity**, en **setup-paden die je niet vindt**.

**Resize:** Electron-window **niet vergrendelen**. Wel: `/control` onder ~768px **hard doorsturen/gaten naar `/operator`** i.p.v. een wegklikbare hint. Setup-tools (`/editor`, `/layout`) blijven desktop-first (`minWidth` 1024 is ok).

## Critical (blokkeert of misleidt tijdens show)

1. **Main vs Solo vs Render-URL is niet begrijpelijk onder druk**  
   Icon-only solo + rode “Solo on air” + Go live + copy-link. TD kan denken dat Solo = Combined render.  
   *Nodig: menselijke keuze over vocabulary en default OBS-workflow.*

2. **`/control` op iPad/phone is gevaarlijk**  
   Alleen stack bij 980px; blijft desktop-dichtheid. Hint is dismissible.  
   *Nodig: redirect/gate onder 768, of echte tablet-control layout.*

3. **`/operate/:id` ≠ `/operator` voor match**  
   Geen manual stoppage, clock visibility, penalties op `/operate`. QR/bookmark-route is incompleet.

4. **Phone Operator mist setup-only widgets**  
   Alleen `operator: true`. Countdown / single LT / message niet bedienbaar; geen pad vanaf telefoon.

5. **Setup-fragmentatie**  
   Clock pill niet in UI; `/project` → editor-link pas na “Save canvas”; `/layout` alleen in header (niet vanaf overlay-kaart); “Custom (layout editor)” navigeert niet.

6. **Dubbele Go live** (kaart + inspector) + **auto-select eerste overlay** bij load → verkeerde target risk.

## Medium (frictie)

- Woorden: overlay / widget / graphic door elkaar  
- F1: live-controls en setup (host, drivers, import, animation) in één paneel  
- F1 import alleen via `/operate` Manual — niet op phone `/operator`  
- Touch targets onder 52px: ticker delete 36px, embedded score 40px, nav 40px  
- Operator ≥768px: smalle 720px kolom — iPad landscape / desk-touch verspilt ruimte

- Editor: inspector toont layout-form vóór selectie (tegen “inspector na selectie”)

| # | Besluit |

### Clarification — tablet + `/control` (vraag 3)

Today: phone/tablet opening `http://host:2014/` go to `/operator`. Someone can still open `/control` on an iPad (bookmark, link, or `?view=control`). That page is a **dense desktop dashboard** (two columns, small fields, icon-only solo). On a 10″ screen it becomes cramped and easy to mis-tap during a show.

Options:
- **A) Always send tablets to Operator** when they hit `/control` (or widths &lt;768), unless they explicitly override — safest for live.
- **B) Build a real tablet layout for `/control`** — more work; only worth it if TDs regularly set up shows on iPad.
- **C) Allow `/control` on tablet only via `?view=control`** — power users keep access; normal links stay Operator.

### Clarification — setup routes (vraag 8)

Today setup is split across:
- **`/project`** — client name, canvas size, branding, asset upload  
- **`/compose`** — “create scoreboard from PNG” wizard  
- **`/editor`** — drag text on one scoreboard  
- **`/layout`** — place *all* overlays on the stage  

A TD often doesn’t know the order: Project → Compose/Editor → Layout → Control live. “One Design hub” would be a single page/checklist with those steps; “keep three routes” means clearer links and naming only.

### iPad landscape advice

| Model | When it wins | When it hurts |
|-------|----------------|---------------|
| **One focused graphic** (`/operate/:id` or Operator with one card) | Live show, thumb reach, fewer mistakes | Can’t see score + ticker at once |
| **Two columns** (score \| ticker/F1) | TD at desk with iPad as mini-console | Crowded; accidental taps; more scroll in Split View |

**Recommendation:** default **focus-first** (one primary widget large; others collapsed or linked). Add a simple **“Desk mode”** toggle later for landscape iPad that shows two operator cards side-by-side — not as the default. Matches QR parity + future custom operator views.
